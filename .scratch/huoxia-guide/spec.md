# 活俠傳劇情攻略網站 Spec

**Status:** ready-for-agent

## Problem Statement

玩《活俠傳》時,玩家面對大量**選項**,不看攻略就不知道選了會走到哪條**路線**、哪個**結局**,也不知道事件為何沒出現(**前置條件**)。現有攻略分散在巴哈姆特、B 站(簡體)、PTT,格式不一、版本混雜,遊戲中很難快速查找。

## Solution

一個純靜態攻略網站:玩家依遊戲時間軸(第 N 年 N 月 → **事件** → **選項** → **後果**)定位當下的選擇,立刻看到後果、前置條件、後續事件連結與**存檔提示**。可依**路線**篩選、全站搜尋;後果預設隱藏以避免劇透。內容為繁體中文、結構化改寫,每個事件附**來源**連結並標註版本。首版即涵蓋全範圍(全流程與各**結局**)。

## User Stories

1. As a 玩家, I want 依第幾年幾月瀏覽事件, so that 我能對應遊戲內目前的時間找到當下的事件
2. As a 玩家, I want 在事件頁看到所有選項, so that 我能對照遊戲畫面上的選擇
3. As a 玩家, I want 點開某選項才看到後果, so that 我不會被劇透
4. As a 玩家, I want 全域切換「顯示全部後果」, so that 我重玩或已通關時能一次看完
5. As a 玩家, I want 看到每個選項的一句劇情結果, so that 我快速判斷要不要選
6. As a 玩家, I want 看到選項帶來的數值變化(好感度、道德、修養等), so that 我能規劃數值路線
7. As a 玩家, I want 看到選項解鎖或錯過的物品、武學、後續事件, so that 我避免永久錯過內容
8. As a 玩家, I want 看到選項是否通往 BE 或某個結局, so that 我避開壞結局或鎖定想要的結局
9. As a 玩家, I want 看到事件出現的前置條件, so that 我知道為何事件沒觸發
10. As a 玩家, I want 看到選項出現的前置條件(時間、數值門檻、先前選項、持有物品), so that 我知道為何某選項沒出現
11. As a 玩家, I want 從選項後果直接點到後續事件, so that 我能追蹤分支走向
12. As a 玩家, I want 在事件頁看到「被哪些選擇觸發」, so that 我能回頭找出要補做的選擇
13. As a 玩家, I want 依路線(龍湘線、唐門線、刺殺線等)篩選事件, so that 我只看我追的那條線
14. As a 玩家, I want 一條路線的事件依時間排序的總覽, so that 我能看完整路線流程
15. As a 玩家, I want 搜尋事件名或選項文字, so that 我能用畫面上看到的字快速定位
16. As a 玩家, I want 搜尋對簡繁用詞寬容, so that 找不到時不會因寫法不同而落空
17. As a 玩家, I want 不可逆分歧點有「建議先存檔」標記, so that 我不會手滑毀掉周目
18. As a 玩家, I want 需要 SL 才能達成好感度的地方有標記, so that 我知道何時該讀檔
19. As a 玩家, I want 結局頁列出每個結局的達成條件與關鍵選擇, so that 我能倒推要走的路
20. As a 玩家, I want 從結局反查必經事件, so that 我能規劃通關路線
21. As a 玩家, I want 每個事件附來源連結, so that 我能核對原文
22. As a 玩家, I want 看到資料適用的遊戲版本與來源日期, so that 我判斷資料是否過時
23. As a 玩家, I want 不同來源衝突時兩邊並列顯示, so that 我能自行判斷
24. As a 玩家, I want 來源沒寫的欄位顯示為「未知」而非猜測, so that 我不會被錯誤資訊誤導
25. As a 玩家, I want 周目或難度差異僅在來源明確提到時才標示, so that 資訊可信
26. As a 手機玩家, I want 網站在手機上易讀易操作, so that 我能邊玩邊用另一個螢幕查
27. As a 玩家, I want 網址可直接分享到某個事件, so that 我能把連結傳給朋友
28. As a 玩家, I want 深色模式, so that 夜間查詢不刺眼
29. As a 玩家, I want 沒有登入或帳號, so that 打開就能用
30. As a 玩家, I want 劇透開關與瀏覽位置在重新整理後保留, so that 不必重複設定
31. As a 維護者, I want 資料以結構化 JSON 存放, so that 補資料不必改程式
32. As a 維護者, I want 載入時自動驗證 schema 與連結完整性, so that 壞資料在建置時就被擋下
33. As a 維護者, I want 驗證能指出孤立事件與單向連結, so that 事件圖保持一致
34. As a 維護者, I want 每筆資料強制有來源與版本, so that 可追溯
35. As a 維護者, I want 來源衝突的標記格式, so that 蒐集時不必二選一
36. As a 維護者, I want 免費靜態部署, so that 沒有維運成本

## Implementation Decisions

- **架構**:純靜態站,無後端、無帳號。前端 Vite + React + TypeScript;資料放 `data/*.json`;搜尋用 Fuse.js 於瀏覽器端;部署 GitHub Pages(repo: `git@github.com:tpma1205/legend-of-mortal.git`)。
- **唯一資料接縫**:`loadGuide()` 讀取 `data/*.json`,輸出已解析的事件圖(事件、選項、後果、前置條件、正反向連結、路線、結局)。UI 只是這個事件圖的薄層。
- **資料模型**(用詞依 `GLOSSARY.md`):
  - 事件:時間(年/月)、標題、前置條件、選項列表、所屬路線、來源。
  - 選項:文字、前置條件(可選)、後果。
  - 後果:劇情結果一句話、數值變化、解鎖/錯過、是否通往 BE 或結局、後續事件連結。來源沒寫的欄位為空,不推測。
  - 前置條件:結構化(時間、數值門檻、先前選項、持有物品)。
  - 存檔提示:不可逆分歧點或需 SL 的標記。
  - 來源:連結、站名、遊戲版本、來源日期;衝突時同欄位並列多筆。
  - 周目/難度差異:僅在來源明確提到時記錄。
- **反向連結**由 `loadGuide()` 計算,不手寫。
- **UI**:時間軸為主幹(年 → 月 → 事件),路線篩選、結局頁、全站搜尋;後果預設收合,全域「顯示全部」開關;事件有穩定網址;響應式、深色模式。
- **內容語言**:繁體中文,採遊戲繁中版用詞;簡體來源轉換並改寫,不整篇轉載。
- **資料蒐集**:以平行子代理依年份與來源分工(巴哈姆特哈啦板、B 站、PTT、4Gamers 等),輸出符合 schema 的 JSON 草稿,再合併、去重、標記衝突,由使用者抽查。
- **範圍**:首版即涵蓋全流程與所有結局。

## Testing Decisions

- 好的測試只驗證外部行為:給定 `data/*.json`,`loadGuide()` 回傳的事件圖是否正確,不測內部實作。
- 唯一測試接縫為 `loadGuide()`,檢查:資料符合 schema、所有連結指向存在的事件、反向連結與正向連結一致、無孤立事件、每筆資料有來源與版本、前置條件結構合法。
- 搭配一組小型 fixture 資料(含衝突來源、空欄位、環狀分支)。
- UI 不另設測試接縫,僅手動驗證一次;專案目前無既有測試可參考。

## Out of Scope

- 使用者帳號、進度同步、留言/投稿。
- 後端、資料庫、CMS。
- 自動爬蟲持續同步來源。
- 主動追蹤周目或難度差異(來源沒寫就不記)。
- 英文或簡體介面。
- 遊戲數值計算器或模擬器。

## Further Notes

- 來源:巴哈姆特活俠傳哈啦板為主要參考;B 站有按年份的完整事件攻略(簡體);PTT 與 4Gamers 為補充。遊戲持續更新,資料需標版本。
- 版權:僅整理事實與結構,以自己的話改寫,附原文連結。
