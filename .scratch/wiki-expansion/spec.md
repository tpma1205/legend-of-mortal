# 以活俠傳 wiki 擴充攻略網站 Spec

**Status:** ready-for-agent

## Problem Statement

目前網站只有「路線時間軸」,資料來自單一玩家作者的攻略,版本未標示、涵蓋有限。玩家還需要查人物、秘笈、技能、道具、丹藥、汗青書、生死簿、風雲史、變心夢,而這些在活俠傳 wiki(CC BY-NC-SA 4.0,遊戲版本 v1.0.3130)已有完整資料。

## Solution

以 wiki 為準(衝突時 wiki 勝出),用轉換腳本把 wiki 的 Markdown 轉成本站 JSON,擴充成多區網站:攻略時間軸、人物、秘笈與技能、道具與丹藥、結局系列(汗青書/生死簿/風雲史)、夢境心上人與變心夢。各區互相連結,全站共用一個搜尋。頁尾標明來源與授權,不使用圖片,網站非商業。

## User Stories

1. As a 玩家, I want 在頂部切換各區(攻略/人物/秘笈與技能/道具與丹藥/結局系列/夢境心上人), so that 我快速找到要查的類型
2. As a 玩家, I want 全站單一搜尋框, so that 我輸入任何名稱都能找到人物、秘笈、道具、事件或結局
3. As a 玩家, I want 簡體輸入也能搜到繁體內容, so that 輸入法不影響查詢
4. As a 玩家, I want 人物頁顯示介紹、陣營、稱號與相關事件, so that 我了解角色並找到他的劇情
5. As a 玩家, I want 夢境心上人頁列出結緣必要條件的步驟, so that 我照著做能結緣
6. As a 玩家, I want 變心夢機制的說明與觸發條件, so that 我知道心上人如何改變
7. As a 玩家, I want 秘笈頁顯示需求、各等級效果與武學點, so that 我決定是否修習
8. As a 玩家, I want 秘笈連到它提供的技能,技能連回秘笈, so that 我雙向查找
9. As a 玩家, I want 技能表依名稱與取得方式搜尋, so that 我找到想要的能力
10. As a 玩家, I want 道具表顯示價格、購買上限、效果、使用與取得方式, so that 我知道買什麼、去哪拿
11. As a 玩家, I want 丹藥與煉丹效果頁, so that 我了解煉丹內容(wiki 尚未收錄的部分明確標示)
12. As a 玩家, I want 汗青書頁顯示名稱、條件與流程, so that 我規劃要達成的結局
13. As a 玩家, I want 生死簿頁顯示死法、條件與流程, so that 我避開或收集驟死結局
14. As a 玩家, I want 風雲史(成就)列表與取得條件, so that 我完成成就
15. As a 玩家, I want 三種結局系列各有獨立列表與編號, so that 它們不被混在一起
16. As a 玩家, I want 事件頁顯示觸發條件、事件流程與備註, so that 我核對遊戲內選擇的後果
17. As a 玩家, I want 事件流程中的選項附數值變化提示, so that 我知道好感度與屬性如何改變
18. As a 玩家, I want 事件、人物、秘笈、道具、結局之間互相連結, so that 我一路點下去不用重新搜尋
19. As a 玩家, I want 事件時間軸依年月旬排列, so that 我對照遊戲內時間找到事件
20. As a 玩家, I want 每頁標示資料版本與 wiki 原頁連結, so that 我能核對最新內容
21. As a 玩家, I want 頁尾授權與出處說明, so that 我知道資料來源與使用條件
22. As a 玩家, I want 手機與深色模式可用, so that 我能邊玩邊查
23. As a 維護者, I want 重跑轉換腳本就能同步 wiki 更新, so that 資料不會過時
24. As a 維護者, I want 每筆資料記錄 wiki commit 與原頁路徑, so that 可追溯
25. As a 維護者, I want 載入時驗證所有跨類型連結, so that 壞連結在建置時被擋下
26. As a 維護者, I want 轉換遇到無法解析的頁面時明確報告而不是默默丟棄, so that 我知道缺了什麼
27. As a 維護者, I want 舊 B 站資料只在 wiki 沒有的地方保留並標示來源, so that 衝突時 wiki 為準

## Implementation Decisions

- **來源與授權**:wiki 為主、衝突時以它為準;資料與網站以 CC BY-NC-SA 4.0 釋出,頁尾標出處,非商業;不收圖片。見 ADR-0001。
- **取得**:`git clone` wiki repo 的 Markdown 到專案外暫存目錄,不收圖片;轉換結果寫入 `data/`。
- **轉換腳本**(`tools/`):依頁面類型各一個解析器,輸出 JSON;每筆記錄 wiki 原頁路徑與 commit;無法解析的頁面列入報告。
- **共用資料模型**(用詞依 `GLOSSARY.md`):人物、秘笈(含各等級效果與武學點、需求)、技能、道具、丹藥、汗青書、生死簿、風雲史、夢境心上人(結緣步驟)、事件(年/月/旬、觸發條件、流程步驟與數值提示、備註)。wiki 的內文超連結(`[[名稱]]`、站內路徑)轉成本站實體連結。
- **事件模型改變**:wiki 事件以「流程文字 + 選項後的數值提示」描述,不是乾淨的選項/後果結構;事件頁改以 wiki 的流程步驟呈現,並盡可能解析出選項與數值變化。舊的選項/後果欄位若無法從 wiki 解析則保留空白,不以 B 站資料硬湊(B 站資料僅補 wiki 缺的事件並標來源)。
- **loadGuide 擴充**:仍是唯一資料接縫,載入全部集合並驗證跨類型連結(事件→秘笈/道具/人物/結局、秘笈↔技能、人物→事件等)。
- **網站**:頂部分區導覽;各區側邊清單與篩選;全站共用搜尋(簡繁寬容);頁尾授權;維持靜態站與 hash 路由;舊事件網址不轉址(網站尚未公開)。
- **範圍排序**:轉換器與共用模型→人物→秘笈與技能→道具與丹藥→結局系列→夢境心上人與變心夢→事件重建與全部連結。

## Testing Decisions

- 好的測試只驗證外部行為。
- 接縫一:`loadGuide()`(既有),擴充驗證跨類型連結與唯一性。
- 接縫二:轉換函式(Markdown 字串 → 實體 JSON),以小型 fixture 頁面驗證(人物、秘笈、結局、事件各一份,含無法解析的頁面)。
- UI 不另設測試接縫,每個階段手動驗證一次。

## Out of Scope

- 稱號、陣營、養成指令、門派設施、江湖眾生相(第二批)。
- 裝備(wiki 尚無資料)。
- 圖片與音樂。
- 英文、簡體、日文介面。
- 帳號、後端、商業用途。
